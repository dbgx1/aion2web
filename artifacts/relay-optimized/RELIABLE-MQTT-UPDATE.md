# MQTT 可靠性更新 · 2026-09-10

通信模块版本：`2026-09-10.reliable-mqtt`。保持 MQTT-only，未恢复 WebRTC。

## 已修复

- 同一 requestId 的发送指令只领取一次执行资格，执行结果写入 SQLite。处理中重复到达不再重复发送，完成后重试返回保存的结果。
- 进程中断留下的未完成指令返回“结果未确认”，不自动重发，避免游戏已收到消息而客户端未记下结果时重复发送。
- 离线事件保存到磁盘，收到 MQTT PUBACK 后才删除；不再按内存队列 500 条上限静默淘汰。PUBACK 表示 broker 已接收，不代表每个控制台都已收到。
- 限制游戏请求并发和等待队列；队列满、等待超过期限的指令明确返回“未执行”。网页给新指令设置 30 秒执行期限，收到回执前不会报发送成功。
- Paho 网络线程的发布确认只入队，由通信线程处理数据库，避免 MQTT 内部锁与应用锁互相等待。
- 聊天和最终结果持久化；中间“已收到”通知和可刷新状态即时发送，不积压、不写盘，减少没有恢复价值的数据库提交。
- 默认客户端编号改为主机名加安装路径摘要，重启后保持不变。手动设置的 AION2_AGENT_ID 不变；从旧版升级时默认编号会改变一次，需要重新选择客户端。

## 存储与参数

默认数据库位于 `%LOCALAPPDATA%/Aion2Relay/`，按 broker、房间、主题前缀和客户端编号隔离。可设置 `AION2_RELAY_DATA_DIR` 更换存储目录。搬迁安装位置时，应固定原来的 AION2_AGENT_ID 并保留数据库，才能沿用队列和去重记录。不要同时运行相同编号的多个实例。

`AION2_COMMAND_WORKERS` 默认 `min(32, CPU 数量 + 4)`，可设置 1–64；本次测试机器为 24。`AION2_COMMAND_CAPACITY` 默认 128，表示执行中加排队的总容量，下限为 workers。控制台未携带期限时，客户端最多等待 30 秒开始执行。

数据库含聊天和指令记录，应按聊天数据保护。离线积压与指令去重记录目前没有自动清理期限，会持续占用磁盘；定期检查磁盘空间。删除数据库会清除恢复与去重依据。本版本保证的是本地提交成功的事件恢复；磁盘故障不在零丢失承诺范围内，MQTT 重投仍需控制台按事件编号去重。

## 更新方式

源码已更新到 `E:\project\aion2\client`。运行源码时正常退出并重启即可。

使用打包的 exe 时，按 README 的新版命令重新打包；本版新用到 Python 标准库 SQLite，命令包含 sqlite3、_sqlite3 和 concurrent.futures.thread 的隐藏导入。没有新增 pip 依赖。

本次提供的是源码更新包，不是完整 exe，也没有验证旧 exe 是否包含 SQLite 运行库。不要直接把本模块覆盖到缺少这些库的旧包中。重新打包后检查日志 `build=2026-09-10.reliable-mqtt`，再确认客户端上线和收发回执。

测试使用真实 MQTT/Paho 和网页通信 hook，游戏 HTTP 为固定延迟模拟，未给玩家发送消息。测试不证明公共 broker、游戏接口或完整控制台页面的生产容量。
