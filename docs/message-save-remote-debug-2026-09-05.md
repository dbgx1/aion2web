# 私聊消息保存失败修复

## 线上原因

2026-09-05，Edge 中 `/messages` 出现“部分消息未保存，服务器拒绝了上传”。通过受支持 CDP 被动记录，并点击现有“重试保存”（仅上传已存在消息，不发送游戏消息），确认 `/api/messages` POST 的 HTTP 状态为 200，但逐会话响应有 `ok:false,status:404,error:角色不存在，请先上传角色信息`。

失败事件是游戏内发出的私聊回显：`direction:S->C`，`jsonData.isFromGame:true`，房间类型 `ONE_ON_ONE`。接收角色尚未进入角色目录；前端正确使用了接收方身份，而服务端要求角色记录预先存在。同批其他会话可正常保存。

## 修复

- `chat-channel.ts` 从明确的私聊事件提取对方身份：发出回显取接收人，收到私聊取发送人。保留大整数 ID 字符串，拒绝不安全数字和缺失身份。
- `messages.server.ts` 仅在缺少角色、事件方向及对方服务器/角色与上传会话一致时补建最小角色记录，再保存原消息。冲突不覆盖已有资料；原有账号隔离和来源消息去重继续生效。
- 没有可信私聊身份的未知角色仍返回原来的失败结果；公共聊天不会创建角色或私聊记录。
