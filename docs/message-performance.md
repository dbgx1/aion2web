# 实时消息页面性能优化

## 已确认的代码路径

- 角色列表按 50 条分页，但滚动后全部保留为 DOM；每行渲染再次解析并遍历最多 500 条实时消息。
- 在线状态每 10 秒轮询所有已加载角色，切换筛选或滚动时旧请求没有取消，也没有防止重叠。
- 角色续页和批量读取重复执行 COUNT；原先全量 12 万角色需要约 1,200 次 HTTP 请求。
- 精确查角色缺少以角色 ID/名称开头的全局索引；跨区服军团过滤和按 ID 翻页的消息历史也有索引缺口。

## 本次修改

- 角色列表固定 72px 行高，按容器高度加前后缓冲渲染；筛选和页签切换重置滚动位置。
- 可见角色消息预览缓存；军团下拉选项独立 memo，输入和实时消息更新不重复构建所有选项。
- 在线状态只轮询可见窗口，200ms 合并滚动变化，取消过时请求，防止并发重叠，后台标签页跳过自动轮询。
- 续页只取数据并沿用首屏总数；筛选变化取消旧续页，防止旧区服数据混入新结果。
- 显式 bulk 参数允许每页 1,000 条且强制不计数；普通请求上限仍为 100。12 万条全量读取约 120 次请求。
- 切换私聊对象取消旧历史请求。
- 0010 迁移只新增索引，不修改角色或聊天记录。

## 验证

- `node scripts/test-character-lookup.mjs`：精确查询、鉴权、分页上限和总数开关。
- `node scripts/test-directory-indexes.mjs`：内存 SQLite 填入 120,000 条角色，检查查询计划命中预期索引且无临时排序。
- `node scripts/test-message-performance.mjs`：浏览器中保留 120,000 条数据，列表末尾实际只渲染 13 行；测试可见区域轮询、输入和滚动重置、旧续页取消、2,500 条批量读取只发 3 次请求。

## 上线与剩余边界

### 下拉框专项修复

生产只读统计确认：122,288 个角色、31 个有数据的区服、14,396 个不同军团。原生军团 select 即便缓存 option 的 React 元素，仍保留上万个原生选项；区服切换还会重建军团菜单。实时消息页的两个筛选器现改为可搜索的虚拟选项弹层，关闭时不挂载选项，展开时只渲染可见选项及缓冲区。

各区服及全部区服的军团列表仅在目录数据变化时计算，使用同一个 Intl.Collator 排序，区服切换直接读取缓存。弹层通过 portal 显示，避免被侧栏裁剪；支持方向键、翻页、首尾跳转、Enter、Escape、Tab 和中文输入法。

实际 MessageCenter 测试使用 14,396 个军团：展开时挂载 13 个选项，本地自动化展开耗时约 44–52ms（包含自动化开销，不是线上 INP 指标）。测试覆盖搜索、不触发角色查询、已选项滚动定位、区服联动、未读筛选、窄屏边界和关闭后的焦点处理。

该下拉框修复已于 2026-09-04 发布，Worker 版本为 `bf5da2d3-c9d7-4c67-83ab-ba46313b6120`，无需新增数据库迁移。

### 种族联动筛选

实时消息页新增全部种族、天族、魔族。按项目 AION2_SERVERS 的区服种族归属筛选；切换种族重置区服、军团和角色搜索。区服选项、军团及人数汇总、未读角色同步限定种族范围。

角色接口支持 `raceId=0|1|2`（省略为全部），使用参数绑定的区服范围条件，与区服、军团、搜索条件取交集；总数、续页和批量读取共用该过滤条件。未知 raceId 返回 400。不需要新增数据库迁移。

SQLite/API 测试覆盖两族隔离、冲突区服返回空结果、总数和跨页一致性、批量读取及非法参数；浏览器测试覆盖种族切换重置、区服/军团联动、未读过滤和所有批量请求保留 raceId。

种族筛选已于 2026-09-04 发布，Worker 版本为 `e87139de-568c-44b8-b73e-bfbdb1d5f702`。

### 刷新后发送按钮禁用

页面卸载时释放占用，但刷新会恢复本地记住的客户端 ID；原先没有重新获取占用，且把“无占用”错误提示成“其他客服操作中”。现在实时消息页确认客户端在线且没有占用后，通过原有服务端接口自动恢复一次；失败可点击“重新占用”。真正由其他账号占用时仍禁止发送并显示账号名称。

占用查询增加请求超时和单请求防重叠；获取/释放占用会使旧轮询响应失效，避免过时的空锁列表覆盖新占用。保留内部导航不释放、退出和页面卸载按 acquiredAt 释放的原有规则。浏览器测试覆盖直接进入、刷新、重试、真实其他账号占用以及迟到的轮询响应；服务端锁与未读筛选回归测试通过。

该修复已于 2026-09-04 发布，Worker 版本为 `58734eed-34dc-47c0-9193-9248a5e81b86`。

### 群发后私聊气泡重复

生产只读核对发现：同一条发送命令的 control_result.response.guid 与游戏 chat_message 的 payload.jsonData.guid 相同，但私聊把 control_sent 和 chat_message 分别渲染成两个气泡；两端时钟还存在数秒偏差。修复通过 requestId 关联回执，再按客户端和游戏 GUID 合并同一私聊中的命令与游戏回传，保留发送状态，使用游戏消息的内容和时间。公频仍保留原始事件。

历史接口只增加 gameMessageId 元数据；通过已有 conversation/request 索引查找跨页回执，限定账号所属会话及客户端，不返回原始请求或请求头。原始聊天记录不删除，不需要迁移。GUID 始终按字符串处理，不使用内容或时间窗口猜测重复，连续发送相同文字仍分别保留。

验证覆盖真实 SQLite 查询和 API 序列化、跨页关联、账号/角色/客户端隔离、事件乱序、历史与实时重放。实际 MessageCenter 浏览器测试确认：两个角色各群发一次各显示一个气泡和成功状态，再发送一次相同文字显示两个气泡；刷新后的历史记录同样合并。

该修复已于 2026-09-04 发布，Worker 版本为 `2e9028de-c75f-4422-be8d-ddba131bda23`。

2026-09-04 已发布到 https://aion2web.cc328496536.workers.dev，Worker 版本为 `514b1090-ce0a-4d52-afbd-d26646043b27`。发布前已核对生产 D1，待执行迁移只有 0010；该迁移已成功执行，6 个新增索引和迁移记录均已核验。首页、消息页及新版 JS/CSS 返回 200，未登录访问角色和消息 API 返回 401。发布后短暂命中过旧版本，后续复查已确认页面引用新版资源。

未来发布仍需核对线上迁移记录；不要直接在未知数据库上重放全部迁移，旧 0005 包含删除聊天表的历史操作。

这是合成数据和本地浏览器验证，不代表线上接口延迟或实际 INP。上线后对比角色 API 延迟、D1 rows_read/query duration、浏览器长任务和 INP。索引应以查询计划和实际读行数验证，参考 [Cloudflare D1 索引指南](https://developers.cloudflare.com/d1/best-practices/use-indexes/)。

现有任意子串搜索使用 instr，仍可能扫描大量记录；普通 B-tree 索引不会解决任意子串搜索。若搜索仍慢，单独评估前缀搜索或兼容中文的搜索索引，并保持产品约定的匹配语义。全量群发/在线查询依然先在浏览器加载全部目标；本次降低读取请求数，但百万级目标应改为服务端持久化任务和分批处理。
