# AI 助手自动调试与完善进度

## 目标

检查和完善手动聊天助手及其共用 AI 链路：多轮稳定性、工具调用完整性、失败恢复、取消与作用域隔离、发送结果可信度、自动化验证。本轮修复已完成并发布，以下记录验证范围和证据边界；不承诺第三方模型永不失败。

## 已采用的设计

- 模型输入与界面记录分开处理。发送前构造模型输入视图，按完整用户轮次保留最近最多 12 轮、64,000 UTF-8 序列化字节；不从中间拆开工具调用与结果。
- 浏览器显示记录也有独立上限：新提问前保留最多 40 轮、192,000 字节。包含新问题再计算预算，避免超长的旧失败轮阻止短问题恢复。
- 完整调用缺少结果时，配对一个明确的 `unknown` 结果，不能伪称成功或失败；参数 JSON 损坏时删除不可解析的调用结构并留下未知结果说明。已有真实结果保留，不执行历史调用。
- 普通回答中出现特定原生工具协议标记时中止本轮，不能把这些文字解析为真实发送；历史中的同类输出在模型输入中替换为异常说明。
- 每次手动助手网络请求覆盖流式响应体的 60 秒期限；缺少结束事件、异常格式与网络异常都通过 RUN_ERROR 结束。正常取消不会被转换成新的错误或重新提交。
- 服务端重复执行输入历史整理，覆盖旧浏览器页面。当前完整轮次超预算返回 413，无效请求返回 400，不消耗上游模型调用。
- 页面上下文不再按字符直接截断 JSON：先删除完整公频记录和其他在线客户端，再删除较旧私聊，保留完整任务、角色和最新私聊。必要内容本身超过 12,000 字符时返回 413，不向模型传递半截任务。
- 每次管理员提问有独立的操作生命周期。工具必须属于当前轮次；停止会取消等待回执和群发，旧结果不能更新新轮次。同一轮重复发送相同内容共享原始结果，包括失败结果；最多允许 8 次模型请求，防止工具循环。
- 手动 AI 私聊等待客户端执行回执，按客户端与请求编号匹配，忽略保留消息。仅确认成功返回 `confirmed`；明确失败返回 `failed`；45 秒超时、断线或提交后取消返回 `unknown`，不自动重发。普通手动发送按钮仍使用原有命令提交提示。
- 手动 AI 群发逐条等待执行回执，分别累计确认成功、失败和结果未确认数量，只有所有角色均确认成功才返回 `sent: true`。失败或未确认即暂停；手动继续保留累计结果，跳过所有已尝试的角色，包括结果未确认的角色，避免重发。普通群发按钮保留原提交流程。

参考：[OpenAI 会话记忆与完整轮次裁剪](https://developers.openai.com/cookbook/examples/agents_sdk/session_memory)、[Anthropic 工具结果配对](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)、[OpenRouter 工具协议](https://openrouter.ai/docs/guides/features/tool-calling)。本项目继续使用已有 TanStack AI / OpenRouter，无供应商迁移。

## 新发现并修复的问题

直接从连接迭代器抛错，会穿过当前 SDK 的 connect→subscribe 桥接，使共享订阅错误在下一轮再次报告。真实 SDK 故障注入测试捕获了该问题。改为标准 RUN_ERROR 终止事件后，后续用户轮次恢复且没有自动重发。

## 自动运行

`npm run test:ai` 顺序执行测试并写入 JSON 报告，任一失败返回非零退出码。UI 测试需可解析的 Playwright（可通过 `PLAYWRIGHT_MODULE_PATH` 指定）及 Edge，或通过 `PLAYWRIGHT_CHANNEL` 选择已安装浏览器。

所有测试模型与游戏均为本地模拟。通过自动化回放不等于真实供应商可用性和回复质量已验证。
