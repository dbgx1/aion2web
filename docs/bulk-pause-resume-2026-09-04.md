# 群发暂停与继续

消息页新增任务面板，显示原客户端、原文案、已提交条数及剩余条数。运行时可点击“暂停群发”（原“停止群发”入口同样暂停）；暂停后点击“继续群发”，或点击“结束本次任务”放弃剩余任务。

## 行为

- 首次完整读取名单后，按区服与角色 ID 去重并保存快照。暂停后的继续不再查询名单，也不重新调用 AI。修改当前筛选、草稿或选择角色不会更改原任务。
- 发送游标在命令提交成功后同步推进，再进入可取消的等待。继续从下一名开始；重复点击继续不会启动两个循环。发送失败尚未提交的当前文案保留，差异化生成器也沿用原实例和索引。
- 暂停任务存在时，新的手动/AI 群发入口拒绝另开任务，要求先继续或结束原任务。结束不撤回已提交的命令。
- 掉线、页面/客户端切换、占用代次变化仍会中止当前循环并保留任务。继续前检查原客户端、当前占用及连接。其他人占用时禁用继续。
- 名单尚未完整读取时暂停，未提交任何命令；继续会按原筛选重新读取名单。

## 边界

进度保留在当前页面会话内，不跨刷新、关闭页面、退出登录或浏览器重启。任务面板明确提示此限制。本次不新增 Cloudflare 服务或数据库写入。

“已提交”代表 MQTT 发布入口返回成功，不代表游戏已执行成功；不会因为回执迟到而自动重发。这不是可靠投递或严格恰好一次保证。跨刷新恢复需要持久化任务与发送确认协议，尚未实现。

旧版本截图中的 77 条任务没有保存原名单和游标，不能从一个计数可靠恢复；本功能适用于升级后新建的任务。

## 验证

- 实际门户浏览器：读取名单时取消；另一人占用后不能继续；恢复占用，修改文案与筛选，再双击继续，仍按原名单与原内容发送下一名，且没有额外名单查询。
- 实际门户浏览器：手动暂停后推进时间不发送，继续后只发送剩余角色；结束未完成任务后可以开始新任务。
- 原消息保存/确认/退避、群发取消、AI 范围隔离、未读及中文输入法回归。
- TypeScript 检查。
- 测试使用模拟 MQTT，不向真实角色发送消息。
