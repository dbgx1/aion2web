# 实时消息未读保留

## 问题与修复

- 原先未读计数直接依赖最近 500 条 MQTT/控制事件。群发回执或公频消息会挤出尚未阅读的私聊，导致未读计数减少。
- `MessageInbox` 在 MQTT 收到私聊时同步登记；未读回复不参与事件日志的 500 条轮换，也不受控制台清空日志影响。已读正文最多保留最近 500 条，已读 ID 在当前会话内保留以抵御重复回放。
- 只有明确点击角色、页面可见且窗口有焦点、消息实际进入私聊可视区域时才标为已读。自动选中首个角色、页面返回、群发模式、后台及滚动区域外的消息不会误清除未读。
- 时间线合并保留源消息 ID，避免游戏消息去重后无法准确关联已读状态。

## 范围

这是当前登录页面会话内的未读状态，支持应用内页面切换；刷新整个网页、关闭页面或退出登录后的恢复及跨设备已读同步尚未实现。旧版本已经丢失的未读状态不会自动恢复。本次不增加 API 轮询或 D1 写入。

## 验证

- `scripts/test-unread-retention.mjs`：真实消息页和 MQTT hook，使用本地模拟 MQTT/API，同一事件循环内注入回复及 650 条回执；检查自动选中、窗口焦点、页面切换、屏幕外消息、重复回放和清空日志。
- `scripts/test-unread-characters.mjs`：未加载角色的未读查找、筛选、已读后的列表保留、私聊时间线及后台可见性。
- `scripts/test-private-chat.mjs`：时间线去重、客户端隔离和历史记录合并。
