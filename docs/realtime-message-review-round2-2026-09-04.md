# 实时消息页面：第二轮审查与修复

## 本轮修改

| 问题 | 修改与验证 |
| --- | --- |
| 发送命令的回执不在当前历史分页中，界面一直显示待确认 | 沿用已有索引，在历史 SQL 中关联同会话、同客户端、同 requestId 的最新回执，返回状态、错误及游戏 GUID；不暴露原始请求。真实 SQLite 测试覆盖分页外成功与失败回执；消息页面测试覆盖刷新和不同客户端相同 requestId。 |
| 加载更早消息失败后，重试读取首页并丢失已加载页；异常游标可重复请求 | 保存失败页游标，重试该页并保留已有历史；校验成功标记、数组和严格递减游标。浏览器验证 HTTP 503、重复游标、再次成功以及角色切换取消。 |
| AI 请求执行期间切换角色、筛选或占用后，旧工具回调可能操作变化后的界面 | 按客户端、角色、筛选及占用代次隔离 AI 会话；范围变化同步禁止旧工具并停止旧请求；停止、清空也禁止迟到回调，提交增加同步防重入。真实 MessageCenter 配合模拟 AI 传输验证四个工具的范围失效，并验证新会话仍能发送。 |
| 失去占用后群发按钮禁用，但输入框仍能按 Enter 进入发送入口 | 群发输入框和 Enter 均检查 canOperate。真实门户测试确认其他操作者占用时输入框与按钮均不可用，运行中的群发在占用丢失后停止。 |
| 未读角色重复查询、重排取消并重查、缺失结果缓存遮盖后来加载的真实角色 | 完整服务器与角色 ID 已知时直接使用目录数据；待查询集合稳定排序；缺失结果缓存为 null，优先显示新加载的准确身份；仅按姓名匹配时仍查询以排除歧义。增加 15 秒超时与响应校验。浏览器验证零冗余请求、重排保留请求、缓存更新和同名歧义。 |

本轮未增加付费服务或数据库迁移。减少的是不必要的查询与错误交互，没有实际账单降幅测量。

测试使用本地 API / MQTT / AI 替身，没有向真实角色发送消息或调用收费 AI。生产构建与上线验证记录见下方。

## 保留边界

浏览器消息缓存仍限于 500 条，尚无持久化 outbox；刷新、关闭页面或持续保存失败时，未保存消息仍可能丢失。MQTT 发送权限与可信桥接端、可靠命令状态机、长期历史虚拟化等架构问题仍见第一轮报告。本轮 AI 停止会取消网页请求，不能撤销此前已经发出的游戏命令，也不保证外部 AI 服务立即停止计费。
