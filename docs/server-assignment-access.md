# 客服区服权限实施说明

已于 2026-09-10 发布到 https://aion2web.cc328496536.workers.dev 。生产数据库迁移 0015_server_assignments.sql 已应用，复查无待执行迁移。Worker 版本 9e8a2a70-1abf-4514-95cf-e71b0514f3af，流量 100%。线上旧注册接口已验证返回 HTTP 410（注册已关闭）。发布记录：artifacts/account-access-deploy.log、artifacts/account-access-deployments.json。

管理员在“客服账号管理”页面（/accounts）创建、启停客服，按区服分配、转交或解除归属。每个区服只有一行归属记录，一个客服可以拥有多行。空归属默认禁止客服访问。停用不自动释放归属，管理员可明确转交。

数据库迁移：migrations/0015_server_assignments.sql。部署代码前须先应用迁移。初始没有任何授权，现有客服需管理员分配区服后才能看到数据。管理员由已有管理员账号或环境管理员登录，创建客服不会自动提升为管理员，公共注册入口关闭。

转交使用版本号作乐观并发控制，旧页面提交返回 409。解除分配保留版本，避免旧请求再次获得区服。数据库触发器与归属变更一同记录旧客服、新客服、操作者和时间。

角色列表、分页、战力排序、搜索、批量查询、数量统计、目录、详情、重点名单、聊天读写和在线状态请求均检查区服权限。上传全局角色数据仅允许管理员或已有服务令牌。读取聊天历史包含该角色历任客服保存的记录，转交后新客服可接续查看；旧客服被拒绝。历史写入仍保留原操作人信息。

每次请求重新读取数据库账号状态和角色，停用后旧会话不再可用。前台每 5 秒及窗口重新获得焦点时检查权限，变化后清空目录缓存并重建页面。后台后续请求立即按新权限判断；已经交付的内容无法撤回，前台发现变更受轮询与网络延迟影响。导出的旧文件不会被追溯删除。

## 2026-09-11：按区服直接操作客户端

客户端占用功能已删除：不再申请、释放、恢复占用，不再轮询或离线上报占用接口。客服只看到所属区服的在线客户端，点击“进入操作”即可聊天或发送控制命令，可在多个已分配区服客户端之间直接切换。客户端未上报区服时对客服隐藏；管理员可以查看所有客户端。

群发在目标客户端区服变化、权限变化或断线时中止。托管通过区服权限接口和 AI 接口核验当前权限，取消后续无权限操作；保留浏览器标签页之间的托管防重复执行及游戏封禁保护。现有 MQTT 协议和客户端心跳无需改动。历史迁移保留以保证旧数据库能按顺序升级，旧 client_locks 表不再读写，无需数据库迁移。

实时聊天与未读角色入口也按授权目录过滤，避免收到其他区服的消息后自动补出角色。验证新增 scripts/test-client-server-access.mjs，覆盖多个区服直接进入、刷新、无权限客户端隐藏、越区命令拒绝及群发中途区服变化。

这是应用内角色范围控制，不代表公共 MQTT 传输层隔离；本次不改造消息代理。

验证：scripts/test-server-access.mjs 使用实际 SQLite 迁移和后台处理器检查归属唯一性、旧版本冲突、解除再分配、审计、账号停用、角色范围、越权读写及聊天交接；scripts/test-account-management-ui.mjs 在 Edge 中验证真实管理组件的创建、转交及搜索操作。
