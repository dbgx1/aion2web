# 托管占用误停修复

远程查看现有实时消息页：A4 的在线托管暂停，已确认发送 2 条、已查 149/65722 人，提示“客户端占用已改变”。另开只读客户端中心确认 A4 仍在线并显示“我正在操作”。未恢复生产任务或发送测试消息。

代码检查和本地回归确认两条可导致误停的路径：

- 同账号重复进入操作会调用 acquire，原 SQL 每次更新 acquired_at。用户没变，托管保存的占用代次却失效。
- 主动获得占用的标签页 pagehide 会释放账号共享锁；其他标签页上的托管因此暂停。仅排除旁观标签页的旧防护不充分。

页面当前状态不能区分当次暂停具体由重复进入、关闭旧页还是历史离线/重新占用触发；上述路径均修复，真实所有权变化仍暂停。

修复：同账号重复 acquire 保持 acquired_at；明确退出后重新获取才生成新代次。网页关闭/刷新不释放账号锁，旧页面发送的 page_exit 也在服务端兼容为无操作。客户端离线、明确“退出占用”仍按原校验释放。

显式点击恢复时请求服务端占用，确认客户端属于当前账号、前端已同步相同代次、房间一致且未封禁，才把该代次绑定到原托管任务。保留收件人、发送进度和会话上下文。后台不会自动接管新代次；其他账号占用或未占用时拒绝恢复。AI 请求和实际发送前仍检查代次。

验证：真实 SQL 锁测试覆盖幂等进入、旧代次不能删除新锁、旧 page_exit 不释放、明确退出释放及其他账号保护；真实页面/SDK 模拟测试覆盖代次变更自动暂停、本人显式恢复继续原任务、其他账号恢复被拒绝、多标签页关闭不释放、刷新复用占用。托管调度、在线扫描、TypeScript 检查通过。

上线后旧页面需要刷新加载新代码；刷新会结束该页面的旧托管任务，需要重新开启。网页关闭后保留的账号占用可在客户端中心进入操作，再点击“退出占用”释放。
